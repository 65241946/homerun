# Homerun 交易策略优化方案 — 信号 / 新闻 / 跟单类

范围：`news_edge`、`news_momentum_breakout`、`certainty_shock`、`traders_copy_trade`、`traders_confluence`（含 `news/edge_estimator.py`、`news/edge_detector.py`、`base.py`、`strategy_sdk.py` 支撑层）。
优化目标：①参数/收益调优 ②逻辑/edge 增强 ③执行/延迟。
分析方式：全文精读源码 + 关键论断逐条对源码核对（下文标 ✅ 的均已核实）。

---

## 0. 动手前必须知道的两件事

### 0.1 你改的文件不是线上跑的那份 ✅
`strategies/` 下这些文件头部都写着：

```
# SEED TEMPLATE — not the live strategy. The DB `strategies.source_code` is the
# runtime master (loaded by the orchestrator + backtester); edits here only seed
# fresh installs / reset-to-factory.
```

含义：编排器和回测器都从数据库 `strategies.source_code` 读代码。直接改这些 `.py` 文件，只影响「全新安装 / 恢复出厂」，**不会改变你正在跑的策略**。正确工作流是：在这些文件里做出「规范版」改动 → 通过 UI/API 热重载或更新 DB 的 `source_code` 推到线上。所有优化改动最终都要落到 DB 那份。

### 0.2 目前没法用数据验证收益，但回测设施是齐的
仓库里**没有历史行情/L2 数据文件**（无 parquet/csv/db），所以离线状态下我无法真的跑回测证明「某个参数改动能提升收益」。下面所有 P1（收益/参数）建议本质是**待验证假设**，需要接上数据后回测确认。回测入口（已核实）：

- 单策略执行级回测：`strategy_backtester.run_execution_backtest(source_code, slug, config, token_ids, start, end, initial_capital_usd)` — 生产撮合引擎 + 延迟/冲击模型；`discover_from_history=True` 才能测「改检测期参数」的效果；`settle_resolution_allow_network=False` 可做严格离线可复现。
- 参数网格扫描：`run_parameter_sweep(source_code, slug, param_grid, train_ratio=0.75, top_k=10)`，`param_grid` 是 `dict[str, list]`，笛卡尔积 + train/test 切分。
- Walk-forward：`backtest/walk_forward.run_walk_forward(..., mode="anchored", n_folds=6, train_ratio=0.5, embargo_seconds=...)`。
- 异步任务队列：`backtest/job_runner.enqueue_run(payload)` → `run_unified_backtest`。
- 需要：canonical parquet 数据面（经 `MarketDataView`）+ 独立回测库 `BacktestAsyncSessionLocal` + 离线 golden settlement store。LLM 类策略在 detect 期仍会实时调 LLM，非纯离线。

⚠️ `strategy_tune_agent.run_strategy_tune_agent(...)` 是一个**基于 LLM 的调参代理，会自动把 `param_updates` 写回 trader 配置**，但它**不跑回测、不做扫描**——只读历史遥测做推理。不建议无监督信任它自动改的参数。

## P0 — 正确性缺陷（静默亏钱 / 静默失效，应优先修，无需回测即可判定）

### P0-1 跟单 copy_delay 与 max_age 两道闸互斥 ✅ 【严重】
`traders_copy_trade.py` 的 `evaluate` 里两个 DecisionCheck：
- `max_age`：`age_seconds <= max_signal_age_seconds`（默认 5s）
- `copy_delay`：`age_seconds >= copy_delay_seconds`（schema 允许配到 300s）

一旦用户把 `copy_delay_seconds` 设得比 `max_signal_age_seconds` 大，两条件不可能同时满足 → **所有信号 100% 被拒，策略静默变哑**，且日志不报错。另外这里的「延迟」是**拒绝年轻信号**而非**延后执行**，没法表达「等 N 秒再进」的真实意图。
修法：(a) 配置期校验 `copy_delay_seconds < max_signal_age_seconds` 否则拒绝保存；(b) 若要真正「延迟进场」，改成把信号挂起到 `age >= copy_delay` 后再执行，而不是丢弃；(c) 默认 `max_signal_age_seconds=5` 偏紧，考虑随实测 `latency_ms` 自适应。

### P0-2 跟单 edge 是「离 0.5 的距离」，不是真 edge ✅ 【严重】
`traders_copy_trade.py:371`：`edge_percent = abs(edge_midpoint(0.5) - entry_price) * edge_multiplier(200)`。
后果：$0.99 和 $0.01 都算出 edge≈98，$0.50 算 0。它和「被跟单钱包的真实优势」毫无关系，却直接喂给 `roi_percent`、`expected_payout`、排序和后续 sizing → 昂贵的近确定性多头被灌了虚高 ROI，公允价附近的单反而 edge=0 被过滤。
修法：edge 应由信号本身推导——被跟单者进场价 vs 当前 mid 的偏移，或 leader 的历史胜率/PnL 折算，而非价格距 0.5 的几何距离。

### P0-3 certainty_shock 用子串匹配排除市场 ✅
`certainty_shock.py:257` `if kw in text:` 用裸子串匹配加密关键词。`"eth"` 命中 "wh**eth**er"/"tog**eth**er"，`"sol"` 命中 "re**sol**ution"，`"xrp"` 等短词同理 → 合法市场被静默排除，加密过滤器过度触发。同仓库 `news_momentum_breakout.py:214` 已有正确的词边界版 `_keyword_in_text`（`\b{re.escape(kw)}\b`）。
修法：把 `_keyword_in_text` 抽到共享工具，certainty_shock 直接复用。

### P0-4 「检测阈值」与「evaluate 回退阈值」两套真值源 ✅
多个策略里检测期用一套阈值、evaluate/custom_checks 又回退到另一套数：
- `news_edge`：配置默认 `min_edge=5.0 / min_conf=0.45`，但 `evaluate` 的 `pipeline_defaults` 回退是 `3.0 / 0.42 / max_risk 0.68`。
- `news_momentum_breakout`：`default_config` 里 `min_liquidity=3000`，`custom_checks` 回退默认 `1500`。
- `traders_confluence`：`min_confluence_strength` 配置 0.50 vs custom_checks 回退 0.55；`min_tier` 配置 "low" vs 回退 "high"。
- `traders_copy_trade`：confidence 缺失时 detect 默认 0.70、evaluate 默认 0.0 → 同一信号先按高置信过检测、再按零置信被 `min_confidence` 拒。
后果：信号过了一道闸却在另一道被不一致地放行/拦截，调参时你以为改了 A 实际生效的是 B。
修法：每个阈值只保留一个来源（配置），删掉散落的魔法回退默认值。

### P0-5 confluence 方向不明时默认做空 ✅
`traders_confluence.py:163` `_resolve_trade_outcome` 对任何缺明确方向的信号返回 "NO"（做空）。对分类不清的聪明钱资金流系统性押空是单向错向风险。
修法：方向不明就丢弃信号，不要猜。

### P0-6 news_edge age=0 被真值判断吞掉
`news_edge.py:290` `_extract_signal_age_minutes` 用 `payload.get("age_minutes") or payload.get("news_age_minutes") or ...`，合法的 `age_minutes == 0`（最新鲜信号）被当假值跳过，取到更旧的 age。
修法：改成 `is not None` 判定链。

### P0-7 certainty_shock 检测的是「漂移」不是「冲击」
`certainty_shock.py:289-293` `up_move = yes - trough`，在 6 小时窗口（`shock_lookback_seconds=21600`）内、最少 5 个点（`shock_min_points=5`）就能触发，没有速度/近因/单调性检查 → 6 小时平缓上漂和 5 分钟真实重定价被同等对待。这很可能是文件头自述「0 胜」的根因。此外该策略的 `max_risk_score=0.70` 闸门恒不生效（风险公式恒 ≤0.62），`shock_min_expected_move=0.03` 与 `min_edge_percent=4.0` 之间有死区（0.03–0.04 的信号被检测出来又在 edge 闸被拒）。
建议：要么按下面 P1 思路重做（加近因/斜率约束），要么先禁用以免拖累组合。

## P1 — 参数 / edge 调优（收益导向，需接数据回测验证）

### P1-1 绝对阈值应改成价格相对阈值（反复出现的主题）
- `news_edge`：edge 闸是绝对百分点（`edge_detector.py:280`），5 个点在 0.05 价位=100% ROI，在 0.50 价位=10% ROI，被同等对待。`fee_adjusted_edge_pct` 在闸后才算。→ 改成直接对**费后 ROI**设闸，或阈值按进场价缩放。
- `news_momentum_breakout`：`breakout_threshold=0.10` 是绝对价格位移（`rise = current - baseline`），0.20 进场的 +0.10 是 +50%，0.70 进场的 +0.10 只是 +14%。→ 改成相对涨幅或按价位缩放。

### P1-2 检测到执行之间没有 edge/时间衰减
`news_edge`、`news_momentum` 都只有硬性 age 截断，没有随信号变旧折减 edge/confidence：59 分钟旧的信号和 1 分钟的同等对待。→ 对 edge/confidence 施加时间衰减（可按类别/`event_type` 设不同半衰期，字段已有）。

### P1-3 news_edge：出场价用的是过期价 + 未用 CI 设闸
edge 是拿 LLM 返回前抓取的 `market.yes_price` 算的（`_build_market_infos`），LLM 批量（并发 3）返回要数秒，市场可能已把新闻消化 → edge 是对一个不再存在的价格测的。同时代码算了置信区间却不用于设闸：点估计过 5% 就放行，即使 CI 跨越市场价（edge 不显著）。
修法：发出机会前**重新拉一次实时价**；对 **CI 调整后的 edge**（`ci_low/ci_high` 落在市场价正确一侧）设闸而非原始点估计。

### P1-4 news_edge：LLM 概率未做校准
两个估计器只在 prompt 里叮嘱「要校准、贴近市场」，没有事后校准（无向市场价收缩、无 isotonic/Platt 映射）。→ 加 `adj = market + k*(model - market)`，`k<1` 由历史实现结果学习，抑制模型过度自信。

### P1-5 两套 news 估计器不统一 ✅（一致性风险）
`edge_detector.py`（async scan 路径）和 `edge_estimator.py`（event 路径）是两个独立 LLM 估计器，schema、prompt、阈值、novelty 逻辑都不同：同一条新闻走不同路径得到不同 confidence/edge，且回测与线上可能走不同路径 → 行为不一致。`edge_detector._estimate_edge` 还**没有超时**（`edge_estimator` 有 20s）。
修法：统一到单一估计器/单套阈值；给 detector 补 `asyncio.wait_for` 超时。

### P1-6 confluence firehose_max_age=720 分钟（12h）太松
「聪明钱正在汇聚」是行为信号，12 小时前的汇聚多半已推动过市场。→ 收紧到分钟~低小时级。同理 confluence 应加**钱包质量加权**：现在 tier 只微调 `risk_score`，不进 size/score，两个低 tier 钱包和两个 extreme tier 钱包几乎等价。→ 按 tier/PnL 加权汇聚强度。

### P1-7 跟单默认没有任何风控预算
`traders_copy_trade` 的 `max_copy_daily_loss_usd / max_copy_source_exposure_usd / max_leader_exposure_usd` 默认全是 1,000,000，`max_copy_drawdown_pct / leader_allocation_cap_pct` 默认 100% → 开箱即用**没有**每 leader / 每日亏损保护。→ 设成有意义的默认（如单 leader 敞口上限、日亏熔断）。

### P1-8 sizing 忽略不确定性
`news_edge` 算了 CI 宽度却只用 `base_size*(1+confidence)`（最多 2x）做 size，没用方差。→ 用 Kelly 类 size 按 edge/方差缩放；SDK 已有 `fractional_kelly_size`（quarter-Kelly）可直接接。

### P1-9 news_momentum 出场逻辑自相矛盾
- scale-out 用 bps（`trigger_bps=30/60` 即 0.3%/0.6%）触发，而 `take_profit_pct=70`、`trailing_stop_pct=18` 用百分数 → 两套不同量纲的止盈/移动止损并存。若 bps 那套生效，0.3% 一跳就减仓 33%，直接和「骑住动量到 +70% 目标」的论点冲突。→ 统一量纲、二选一。
- `target_distance_to_one_fraction=0.55` 把 `expected_payout` 设成「到 1.0 剩余距离的 55%」，低价进场时把 advertised edge 灌高（0.2 进 → 目标 0.64），乐观目标反而更容易过 edge 闸。→ 重新标定或按类别设。
- 动量停滞出场要求「价格 ≤ 进场价」才触发：一笔冲高后停滞、仍浮盈 40% 的单不会停滞出场，要一路回吐到成本才触发。→ 改成「≤ 追踪高点 − X」或按回吐比例设。

## P1.5 — 内存泄漏（长跑进程）
`news_momentum_breakout`、`certainty_shock` 的 `self.state["price_history"]` 为**每个见过的市场**建 key 且从不回收停更市场的 key（虽然单市场的 deque/list 有长度上限）。长跑进程无界增长。→ 加市场级 GC，淘汰长期不出现的市场 key。另 `news_momentum` 的 deque `maxlen=240` 可能让 `stale_history_seconds=1800` 永远够不到（刷新快于 7.5s 时 240 点跨不到 1800s）→ 用 `stale_seconds/refresh_interval` 反推 maxlen。

## P2 — 执行 / 延迟

### P2-1 news_edge：LLM 在关键路径上且无结果缓存
`detect_edges` 每次 scan 从头重算，`_cached_edges` 只事后存不查用 → 同一 (article, market) 每 60s scan 都付一次全新 LLM 调用。→ 按 (article, market, 价格分桶) 缓存结果跳过未变对；只对新/未嵌入文章做 embedding（现在每 scan 重嵌 7 天 TTL 内**全部**文章）。

### P2-2 detector 无超时会拖垮整批
`edge_detector._estimate_edge` 无超时，一个卡住的 provider 调用会拖住整个 `asyncio.gather`。→ 补 `asyncio.wait_for(20s)`（与 estimator 对齐）。

### P2-3 confluence 重复计算
`evaluate_firehose_signal` 在 `apply_firehose_filters` 和 `build_opportunities_from_firehose` 各跑一次（每信号被 gate 两遍）；`normalize_trader_signal` 每遍 3–4 次；`_effective_config()` 反复重建（每次 dict copy + 校验）。→ 去重 + memoize。

### P2-4 copy_trade：每次 evaluate 都全量校验配置
`validate_traders_copy_trade_config` 在**每个信号的** `evaluate()` 里跑 ~25 个强制转换 + 多个规范化 → 应缓存到 `configure()` 一次。`_to_utc` 同一时间戳被解析 3 次，解析一次即可。

### P2-5 news_momentum：正则每关键词每市场每周期重编译
`_keyword_in_text` 每次 `re.search(rf"\b{re.escape(kw)}\b", ...)` 不缓存，横跨 ~11 加密 + ~17 体育提示词、每个市场每周期反复调。→ 类加载时预编译 pattern。deadline/市场文本同理可按市场版本 memoize（certainty_shock 的 `_parse_date_string` 里还在函数内 `import calendar`、每周期重算静态 deadline）。

### P2-6 copy_trade/confluence 无真正异步
`copy_trade.detect_async` 只是同步包装；confluence 同时有轮询 `detect_async(limit=250)` 和事件驱动 `on_event`，事件在流时轮询是多余延迟。→ 事件驱动优先，去掉冗余轮询。

## 建议执行顺序

1. **先修 P0**（尤其 P0-1 死锁、P0-2 假 edge、P0-3 子串匹配、P0-4 双真值源）——这些是明确 bug，不需要回测就能判定，且直接对应「静默失效/虚高 ROI/错向」等真实亏损来源。改动落到 DB `source_code`（见 0.1）。
2. **接数据 + 跑基线回测**：用 `run_execution_backtest`（`settle_resolution_allow_network=False`）对每个目标策略跑一版当前基线，再用 `run_parameter_sweep` / `run_walk_forward` 验证 P1 的每个参数假设。没有基线，P1 的收益改动都是盲改。
3. **P1 逐条 A/B**：优先 P1-1（费后 ROI 设闸）、P1-3（实时价 + CI 设闸）、P1-7（跟单风控默认值）——预期性价比最高。
4. **P2 执行/延迟**：在正确性和收益逻辑稳定后再做，避免过早优化掩盖逻辑问题。
